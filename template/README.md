# 简历版式研究 (2026-08-15)

> 用途: UI 重设计前的一次性调研沉淀。每份文档 = 一种版式: 结构图 / 字段容量 / 优点缺点 / 平台解析兼容性 / 代表模板 / 对 CV 项目的适配要点。
> 本项目硬约束: Boss/智联智能解析 + OCR 友好 + A4 打印 + 无构建原生 HTML/CSS/JS。选版式时**平台解析兼容性是一票否决项**。

## 版式总览与选型表

| # | 版式 | 文件 | 字段容量 | 平台解析 | 适合谁 |
|---|------|------|---------|---------|--------|
| 1 | 单栏时间序 (ATS 标准) | [01-single-column.md](01-single-column.md) | 中 | ✅ 最佳 | 所有人, 尤其求稳 |

**CV 项目当前版式 = 1 号 (单栏), 头部是「左信息右头像」变体。**

## 头部 (profile 区) 变体 — 当前痛点的主战场

头部是字段密度最高的区域, 独立于主体版式, 有 4 种变体 (详见 01 号文档头部章节):

| 变体 | 结构 | 容量 | 备注 |
|------|------|------|------|
| H1 左信息右头像 | icon+text 两列网格 + 右侧头像 | ~8 条 | **CV 现状**; 头像吃掉 1/4 宽度 |
| H2 无头像三层收束 | 姓名+岗位 / 联系方式行 / 期望标签行 | ~10 条 | billryan 式, 解析最稳 |
| H3 居中极简 | 全部居中, 名字大, 一行 `·` 分隔联系 | ~6 条 | crispgm 式, 最干净容量最小 |
| H4 侧栏收纳 | 联系方式全进侧栏, 头部只剩姓名+岗位 | 侧栏不限 | 跟 2 号版式绑定 |

## 结论速记 (给未来的自己)

- 求稳 + 平台解析优先 → **1 号 + H2 头部**, 头像做成可开关
- 字段真的多到放不下 → 2 号, 但要实测 Boss/智联解析再上线
- 4/5 号只适合做「展示版」, 不适合做「投递版」
